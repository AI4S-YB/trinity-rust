# 真实数据基准：拟南芥 chr5 转录组——trinity-rust vs 原版 Trinity vs StringTie（2026-08-19）

## 数据与流程

- **数据**：ENA PRJDB8006（拟南芥幼苗，暗/光处理，MiSeq PE 76bp）3 个 run 合计 1.49M 对
  reads；hisat2 比对 TAIR10（77.4% 比对率）→ 抽取**仅比对 chr5 的 read 对 205,326 对**
  （约 2× 每基因覆盖——低深度场景）
- **参照**：StringTie 2（同 reads + TAIR10 chr5 注释，参照引导）→ 5,364 条去重转录本
- **对比**：minimap2 asm5（query=de novo，target=StringTie），恢复率按参照最佳命中分档，
  精确度按 de novo 碱基能以 ≥95% id 比上参照的比例

## 结果（对 StringTie 参照）

| 指标 | trinity-rust（经典单遍） | 原版 Trinity v2.15.2（递归默认） |
|---|---|---|
| 转录本数 | 4,574 | 4,668 |
| 总 bp | 2,218,372 | 2,301,004 |
| N50 | 584 | 596 |
| **全长恢复（≥95%cov&≥95%id）** | **111 (2.1%)** | **110 (2.1%)** |
| ≥90% 恢复 | 229 (4.3%) | 232 (4.3%) |
| ≥70% 恢复 | 724 (13.5%) | 735 (13.7%) |
| 精确度（碱基级） | 85.3% | 84.1% |
| **全程 wall** | **~7.5 分钟** | **~33 分钟** |

**双方输出的相互重叠**：精确序列交集 4,019 条（覆盖原版 86.1% / 覆盖我们 87.9%）——
远高于 sample_data 上的 50% 带（低深度下多数基因只拼出 1-2 条 contig，两种架构收敛）。

## 判定

1. **对 StringTie 的接近程度：统计平手**——每一项指标都在彼此 1-2% 内（全长恢复 111 vs 110）。
   在此真实数据上，trinity-rust 与原版的组装质量不可区分，且**快约 4.4×**。
2. 绝对恢复率低（2.1%）是场景属性而非实现差异：~2× 每基因覆盖 + 76bp 短读 + 参照引导的
   StringTie 拥有压倒性先验优势（同样的低深度下 de novo 只能出片段，双方 N50 都 ~590bp）。
3. 本次原版走的是 v2.15.2 **递归默认**流程（4524 个分区迷你流程），我们是经典单遍——
   跨架构对比在低深度下依然收敛到等价输出（见 docs/architecture-discovery.md）。

环境：登录节点 8 线程 / 4GB 上限 / 双方默认参数（--no_bowtie --no_salmon）。
