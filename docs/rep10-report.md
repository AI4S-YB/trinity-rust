# 十次重复实验：与原版输出的重合度统计判定（2026-08-19）

数据：sample_data 全量 PE；两侧各以**默认模式**（原版并行 inchworm / 我们 PARALLEL）独立跑 10 次。
派发背景：单次端到端对拍（57-70% 双向覆盖）无法区分"原版自身随机性"与"系统性实现差异"，
用 10×10 采样定论。

## 结果

| 指标 | 原版×原版 (45 对) | 我们×我们 (45 对) | 我们×原版 (100 对) |
|---|---|---|---|
| 转录本数/次 | 77–98（中位 83.5） | 71–75（中位 73） | — |
| 精确序列多重集覆盖（中位[范围]） | **84.1%** [69.5, 95.1] | **95.9%** [86.7, 100] | **49.3% / 41.6%** [42-53 / 35-49] |
| 31-mer 内容池 Jaccard（中位） | 92.97% | 94.60% | 80.27% |
| 基因数（10 次平均） | 58.5 | 58.6 | — |
| 平均异构体/基因 | 1.46 | 1.24 | — |
| ≥2 异构体基因占比 | 15% | 17% | — |
| 核心集（≥8/10 次出现的序列） | 68 条 | 70 条 | 交集 35 条（50.0/51.5%） |

同源交叉喂（同 inchworm 输入，确定性模式）：bundle 逐字节一致；58 组件中 28 个
allProbPaths 序列多重集完全相等；差异组件的独有序列**中位 k-mer 共享率 100%**（43 条原版
独有中 41 条 ≥90% 共享、仅 1 条 <50%）——同内容、不同异构体切分。

## 判定

1. **统计可区分**：跨实现精确覆盖（49%）远低于两侧自重合带（96%/84%）——差异含**系统性
   成分**，非纯原版随机平局。修正此前"跨实现带与自重合带同量级"的说法。
2. **系统性差异的来源**：各实现的哈希迭代序构成**固定偏好**——inchworm 种子序
   （`__gnu_cxx::hash_map` vs FxHashMap）与 Butterfly 的 Java HashMap/JUNG HashSet 序。
   确定性模式下同实现 A≡B 逐字节、跨实现仍 62%（contig 层）即其证据。
3. **内容层面对齐**：基因集合一致（59/59）、多异构体基因占比相同、差异序列中位 k-mer 共享
   100%——缺的不是序列内容，是同一基因座的异构体边界划分（原版多报约 0.2 个异构体/基因）。
4. **我们的自一致性优于原版**（95.9% vs 84.1%）——输出更稳定。

## 若需逐字节闭合（"兼容模式"，未实施）

P2 已证明：同种子序 → inchworm 逐字节。因此闭合路径明确：复刻 `__gnu_cxx::hash_map`
迭代序 + libstdc++ introsort 平局行为（inchworm 层，~1-2 天）；复刻 Java HashMap 桶序
（EM 输出序已有 `java_hashmap_order` 先例）与 JUNG HashSet 序（butterfly 层，~2-3 天）。
收益=输出分布与原版不可区分；成本=引入对原版二进制内部数据结构的强耦合。生产组装用途
下内容等价 + 更高稳定性通常优于逐字节模仿（记录为决策，需要时按上述路径实施）。
