### Task 1: junction 25-mer 提取 + 融合纯函数（butterfly, TDD）

**Files:** Modify `crates/trinity-butterfly/src/component.rs`, `crates/trinity-butterfly/Cargo.toml`

- [x] **Step 1: 写失败测试——`junction_kmer25(u_name, v_name) -> Option<String>`**

手算用例锁定（复用 `trinity_flow::paths` 的最长后缀-前缀重叠函数）:
- 正常: u="...24 碱基尾部 X", v 延伸首碱基 b → Some(X+b)（25 碱基）
- u 不足 24: 向前借 v 延伸补足 25；拼接仍不足 25 → None
- v 被 u 后缀完全包含（无延伸碱基）→ None

- [x] **Step 2: 写失败测试——`fuse_cov(w_raw, cov, cap) -> u64`**

- w_raw ≥ 1 → 原样（read 证据不动，含恰好=1 的证据边）
- w_raw == 0, cov ≥ cap → cap；0 < cov < cap → cov；cov == 0 → 1
- cap == 0 非法（构造侧断言）

- [x] **Step 3: 实现两函数 + `digraph_to_flow` 改签名**

```rust
fn digraph_to_flow(
    g: &DiGraph,
    read_cov: &FxHashMap<(i32, i32), i64>,
    cov: Option<(&trinity_kmer::counter::CountMap, u64)>, // (表, cap)
) -> trinity_flow::graph::FlowGraph
```

融合逻辑（spec 公式）:
```rust
let w = pog_w.max(read_w);
let w = if w == 0 {
    match cov {
        Some((table, cap)) => {
            let c = junction_kmer25(&u_name, &v_name)
                .and_then(|k25| lookup_cov(table, &k25)) // DS canonical, 缺=0
                .unwrap_or(0);
            (c.min(cap)).max(1)
        }
        None => 1,
    }
} else { w };
```

- 25-mer 查询: `kmer_to_intval` + `get_ds_kmer_val(·, 25)`（trinity-common）,
  表缺 → 0; 编码失败（非 gatc）→ 0。
- `ComponentParams` 增字段: `flow_cov: Option<(std::sync::Arc<trinity_kmer::counter::CountMap>, u64)>`,
  默认 None（`Default` 派生/构造点同步改）。
- **注意**: digraph_to_flow 现有调用点（M3 read support 段与单节点分量段）
  同步更新; None 时输出与现版逐边一致（回归断言）。
